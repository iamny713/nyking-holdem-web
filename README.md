# NYKING Holdem Web

React + TypeScript + Vite 기반의 한국어 홀덤 학습 웹 앱.

## 실행

Node.js 22.18 이상 또는 24 이상 권장.

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

## 기능

- 핸드 두 개를 선택하여 1~1,000,000회 몬테카를로 시뮬레이션. 승률, 무승부, 에퀴티, 진행률 및 중단 기능. Web Worker에서 계산.
- 자료, 내 포지션, 유효스택, 상대 오픈 포지션에 따른 오픈 / 플랫콜 / 3벳 13×13 매트릭스.
- 레인지의 핸드를 클릭하고 시뮬레이터로 전달. 수딧은 스페이드, 오프수트·페어는 스페이드/하트 대표 조합 사용.

## 콤보 계산기 (세 번째 탭)

상대 포지션·깊이·관찰 액션(오픈, 플랫콜, 일반 3벳, 선제 올인, 리쇼브, 올인 콜)을 입력하면 현재 보수적 추천 모델에서 해당 액션의 레인지를 가져옵니다. 상대의 실제 성향을 학습한 분포나 GTO 역추정이 아니며 조건부 블러프 후보는 자동 포함하지 않습니다. 필요하면 핸드 클래스를 직접 추가/제거할 수 있고, 상황 변경 시 직접 수정은 해제되어 새 모델 범위를 사용합니다.

- 상대 레인지 안의 타깃 핸드 클래스를 선택합니다. 페어/수딧A/AK/전체 레인지 빠른 선택을 지원합니다.
- 내 카드 2장, 커뮤니티 5장, 기타 데드카드 3장을 블로커로 입력할 수 있습니다. 중복 카드는 차단하며, 보드는 입력 중인 장수도 즉시 제외합니다.
- 모든 개별 두 장 조합을 열거하고 블로커와 겹치는 조합을 제거합니다. 페어 기본 6, 수딧 4, 오프수트 12콤보입니다. 각 조합은 동일한 가중치입니다.
- 주 비율: 남은 타깃 콤보 / 남은 상대 레인지 콤보. 별도로 전체 가능한 두 장 조합 `C(52 - 블로커 수, 2)` 중 상대 범위와 타깃의 비율을 표시합니다. 승률이 아닙니다.
- 상세보기에서 타깃별 블로커 적용 전후 수와 실제 카드 조합을 확인합니다. 빈 레인지의 비율은 0%로 오해하지 않게 `—`로 표시합니다.
- 모바일: 접을 수 있는 입력, 고정 결과 요약, 높은 랭크별 큰 핸드 버튼, 무늬별 바텀시트 카드 선택(자동 다음 슬롯 이동·키보드 포커스 제한·닫기), 390px 가로 넘침 검사.

## 자체 추천 전략 (기본 모드)

자료의 전략 원리를 참고해 직접 설계한 **9맥스 토너먼트 추천 레인지 v1.2.0**입니다. 솔버 계산, 모델 훈련, 균형 검증을 수행한 전략이 아닙니다. GTO EV나 정밀한 혼합 빈도를 표시하지 않습니다.

- 기본 조건: 9명, 전원 동일 스택, SB 0.5BB / BB 1BB, BB 앤티 1BB, chipEV, 레이크 없음, ICM/바운티 미반영.
- 일반 깊이: 15 / 20 / 25 / 30 / 40 / 60 / 80 / 100BB. 첫 진입과 한 명의 일반 오픈에 대한 대응을 제공합니다.
- AOF: 실제 1~10BB 선택. 레퍼토리는 1~4 / 5~7 / 8~10BB 세 구간으로 나눕니다. 첫 진입은 올인/폴드, 한 명의 선제 올인에 대한 대응은 올인 콜/폴드로 별도 설계했습니다. 1~4BB의 극단적 숏스택은 실제 팟오즈 차이가 커 구간 공통 추천 오차가 특히 클 수 있습니다.
- 액션 색상: 오픈, 플랫콜, 일반 3벳, 올인, 올인 콜, 폴드. 각 핸드는 기본 액션 하나와 선정 이유를 갖습니다. 상단 %는 1,326 조합 중 그 액션의 레인지 비중이며 핸드의 액션 빈도/승률이 아닙니다.
- SB는 림프를 생략한 단순화이며, 일반 오픈 대응에서 30BB 이하는 SB 플랫콜을 생략하고, 40BB 이상은 상대 위치별로 플랫콜을 허용합니다. v1.3.0은 BB의 마지널 방어도 별도 구성하며 BB 대 SB에서는 포스트플랍 포지션을 반영합니다. 표시된 작은 오픈·콜러 없음 기준의 자체 설계이며 솔버 검증 범위가 아닙니다. 15/20BB 재공격은 올인으로 단순화합니다. 25/30BB는 일부 리쇼브와 일반 3벳을 구분합니다.
- 오픈 사이징: 15~25BB 2BB, 30~60BB 2.2BB, 80~100BB 2.3BB. SB는 0.5BB 더 큰 오픈(최대 3BB)을 가정합니다. 대응 차트도 오픈 위치의 사이징을 사용합니다.
- 상대 올인 콜은 AOF 모드에서만 제공합니다. 림퍼, 추가 콜러, 이미 발생한 3벳, 스택 불균형, 다른 인원수의 차트는 지원하지 않습니다.

`src/recommendations.ts`의 포지션별 명시적 오픈 레퍼토리와 상황별 대응 규칙으로 생성합니다. 자료의 차트를 토너먼트로 보간하거나 재분류한 결과가 아닙니다. 저자 교재의 스택·임플라이드 오즈·지배 위험·포지션 원리와 PDF의 밸류/콜/재공격 구조를 참고했으며, 개별 핸드 경계·사이징·올인 배치는 앱의 자체 설계입니다. 전략의 수익성은 검증하지 않았습니다. 80/100BB 등 일부 깊이는 같은 범위를 공유합니다.

테스트는 352개 일반 상황과 440개 AOF 상황에서 핸드 누락, 액션 중복, 콤보 합계, 불가능한 액션과 구간 전환을 검사합니다. 이 검사는 포커 전략이 GTO인지 검증하지 않습니다.

기존 원문 차트는 **원문 차트 참고** 모드에 보관했습니다.

### 보수적 조정 v1.1

전체 깊이의 오픈·콜·3벳·올인·올인 콜에서 경계 핸드를 제외했습니다. 기존 폴드를 진입으로 바꾸지 않는 축소 조정이며, 원문 참고 차트는 유지합니다. UTG/UTG+1의 ATo는 모든 지원 깊이에서 폴드입니다. 15BB UTG는 `77+ AJs+ KQs AQo+`입니다. 이 보수적 조정은 GTO 최적화나 폴드의 +EV 검증을 의미하지 않습니다.

내 포지션과 상대 포지션은 버튼으로 선택합니다. 원문 참고 모드도 동일하게 버튼을 사용합니다.

### 3벳 전략 노트 v1.2

일반 3벳을 밸류 중심 / 리니어 확장 / 블러프로 분류하고 색상으로 구분합니다. `src/three-bet-study.ts`의 조건부 후보는 기본 액션이 콜 또는 폴드인 핸드에만 표시합니다. 30BB 이후 일부 상황에서 휠 수딧 에이스를, 깊은 스택·늦은 오픈·IP의 제한된 상황에서 수딧 고카드를 학습용 후보로 제시합니다. 기존 보수적 액션과 비중은 바꾸지 않습니다. 후보의 개수·콤보 수는 사용 빈도가 아니며 모든 후보를 함께 사용하라는 뜻도 아닙니다.

핸드를 누르면 검토 조건 / 제외 조건 / 4벳 대응 미지원 안내를 보여줍니다. 이 후보는 솔버 해나 +EV 계산 결과가 아니며, 최적 블러프:밸류 비율·빈도·EV는 제공하지 않습니다. 일반적인 레인지 구조 참고: https://blog.gtowizard.com/preflop-range-morphology/

## 자료 기반 레인지

앱의 **레인지 기준**에서 아래 세 가지 모드를 선택합니다.

- PDF 참고 모드: 사용자 제공 The Ultimate Cash Game Preflop Guide (2026)의 100/200BB 캐시 차트. 8개 포지션의 오픈 14개와 오픈 대응 56개를 수록했습니다. 핸드별 레이즈/콜/폴드를 이미지 색상 폭에서 약 1% 단위로 복원했습니다. 원본 솔버 빈도나 EV가 아닙니다. 전체 액션 비율은 원문 헤더와 0.25%p 이내인지 테스트합니다. 앞선 오픈은 3BB(SB 4BB), 대응 레이즈는 10BB(블라인드 12BB)로 차트에 표기됩니다. 앤티와 레이크 세부값은 자료에 기재되어 있지 않습니다. SB RFI의 Call은 림프/컴플리트입니다.
- EPUB 참고 모드: 사용자 제공 Mastering Small Stakes No-Limit Hold’em의 기본 오픈 Diagram 1, 3, 7, 8, 14, 16, 19, 21. EP/MP/CO/BTN의 저자 기본 전략이며, 12~40 미만 / 40~100BB 구간을 사용합니다. 40BB 경계는 두 구간 중 깊은 구간을 적용합니다. 각 차트의 선택된 핸드 조합 수가 원문의 합계와 정확히 일치하는지 검증했습니다. EP/MP 그룹을 특정 9맥스 좌석에 자동 대응시키지 않습니다. 상대 성향별 조정은 설명으로 제공하며 수치를 자동 수정하지 않습니다. SB 림프 및 오픈 대응 차트는 이 모드에 수록하지 않았습니다.
- 9맥스 토너먼트 모드: UTG / UTG+1 / UTG+2 / LJ / HJ / CO / BTN / SB / BB 설정을 유지합니다. 제공 자료를 이 조건의 GTO로 재분류하지 않으며 해당 데이터는 미연결로 표시합니다.

자료가 없는 스택/포지션/액션은 빈도 0%나 폴드 추천으로 표시하지 않고 데이터 없음으로 구분합니다. 원문 PDF/EPUB와 추출된 이미지는 저장소에 포함하지 않습니다. 웹 배포나 GitHub 업로드는 이번 작업에서 수행하지 않았습니다.

## GitHub Pages 배포 설정

`vite.config.ts`는 프로덕션 빌드 경로를 `/nyking-holdem-web/`로 설정합니다. 개발 서버는 `/`를 사용합니다. `.github/workflows/deploy-pages.yml`은 main 푸시 시 Node 24에서 npm ci → 테스트 → 빌드 → Pages 배포를 실행합니다. 저장소의 Settings → Pages에서 GitHub Actions를 배포 소스로 선택해야 합니다.

예정 주소: https://iamny713.github.io/nyking-holdem-web/

두 페이지를 공개로 배포합니다. 전체 앱: https://iamny713.github.io/nyking-holdem-web/ · 시뮬레이터 전용: https://iamny713.github.io/nyking-holdem-web/simulator/

시뮬레이터 전용 진입점은 레인지·콤보 계산기 모듈을 불러오지 않습니다. 두 페이지는 HandSimulator 컴포넌트와 Web Worker를 공유합니다. 저장소는 공개입니다.

## 커뮤니티 카드 승률 계산

공용 HandSimulator에 프리플랍 / 플랍 / 턴 / 리버 선택을 추가했습니다. 프리플랍은 기존 N회 몬테카를로, 플랍은 고정 3장을 제외한 턴·리버 990가지, 턴은 리버 44가지를 전수 계산합니다. 리버는 확정 보드에서 한 번 판정합니다. 알려진 손패와 보드는 중복될 수 없으며, 카드나 스트리트가 바뀌면 진행 중 계산과 이전 결과를 무효화합니다. 프리셋 손패가 기존 보드와 겹치면 그 보드 슬롯을 비웁니다.

양쪽 모두 단독 승률과 에퀴티(승률 + 무승부율 / 2)를 별도로 표시하며, 에퀴티 50% 미만인 쪽을 열세 핸드로 강조합니다. 에퀴티는 팟 지분이며 단독 역전 승률과 다릅니다. 전체 앱과 시뮬레이터 전용 페이지가 동일한 컴포넌트·Worker를 사용합니다.

### PokerData 개인 솔버 조회 (로컬 시험 기능)

네 번째 탭에서 NLHE MTT 8-max (`nlmtt8`)의 저장된 해를 조회합니다. 개인 API 키는 해당 origin의 localStorage에 저장하고 삭제 버튼으로 제거합니다. API 키와 받은 전략 데이터를 저장소에 넣지 않습니다. 스택별 `/spots` 목록을 한 번 조회한 뒤 실제 경로를 따라 액션을 선택합니다. 현재 차례 강조, 이전 액션 되돌리기, 내 차례까지 폴드 이동을 지원합니다. 종결 액션은 후속 노드 목록에 없을 수 있어 전체 액션은 `/node` 결과에서 확인합니다.

기본 결과는 혼합 빈도를 유지하는 간소화 보기이며 상세 보기에서 전체 액션 EV와 169 핸드 행렬을 제공합니다. `/config`의 팩 오픈 표기와 `/node`의 실제 `sizeBb`를 구분합니다. 결과 조회 시 앞선 레이즈 노드를 함께 가져와 실제 사이즈를 표시하고 요청 전 최대 API 호출 수를 안내합니다. 결과·목록 캐시는 탭 메모리에만 존재합니다. 이 기능은 신규 계산, 임의 사이징, 9맥스, ICM 해를 제공하지 않습니다. 10BB는 전원 동일 스택이 아닌 특수 AOF 데이터입니다.
